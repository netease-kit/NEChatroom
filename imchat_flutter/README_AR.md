# Im Chat — إعادة بناء Flutter

هذا مجلد مستقل داخل المستودع، ويحتوي على هيكل Flutter قابل للتطوير اعتمادًا على تحليل ملف APK واستخراج الأصول، مع ربط وظائف أساسية بمشروع Supabase.

## الموجود في هذه المرحلة
- تسجيل الدخول وإنشاء حساب بالبريد وكلمة المرور عبر Supabase Auth.
- إنشاء ملف المستخدم الأولي وتحديث الاسم.
- عرض الغرف النشطة وإنشاء غرفة عامة/خاصة والانضمام إلى الغرف العامة.
- محادثة نصية لكل غرفة مع Supabase Realtime.
- عرض آخر الرسائل والغرف المرتبطة بها.
- عرض الملف الشخصي والمحفظة.
- واجهة خدمات أولية لقراءة العائلات والوكالات والهدايا وباقات VIP والإشعارات.
- إنشاء عائلة أو وكالة من الحساب الحالي، مع الالتزام بسياسات RLS الموجودة.

## إعداد التشغيل
يتطلب Flutter SDK حديثًا وDart 3.3 أو أحدث.

```bash
cd imchat_flutter
flutter pub get
flutter run \
  --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
  --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_SB_PUBLISHABLE_KEY
```

لا تضع Service Role Key أو Agora App Certificate داخل التطبيق. استخدم Publishable Key فقط، واترك الصلاحيات لسياسات RLS ودوال Edge Function.

## حدود مهمة
- هذا ليس سورس Flutter الأصلي المستعاد؛ ملفات APK لا تعيد عادةً مشروع Dart الأصلي.
- الأصول المستخرجة كبيرة (أكثر من 140MB) ولم تُرفع إلى GitHub في هذا الفرع لتجنب تجاوز حدود ملفات GitHub؛ احتفظ بحزمة الأصول المنفصلة وأضفها محليًا عند الحاجة.
- لم يتم بناء APK أو اختباره في بيئة هذه المهمة لعدم توفر Flutter SDK.
- الصوت/الفيديو وAgora، الشحن والمدفوعات، الألعاب، الفيديوهات/اللحظات، المتجر الكامل، الهدايا الفعلية، وواجهات الإدارة المتقدمة تحتاج تنفيذًا واختبارات إضافية.
- لا تنفذ شحنًا أو خصمًا من رصيد العميل من التطبيق مباشرة. العمليات المالية يجب أن تمر عبر RPC/Edge Functions موثوقة وتتحقق من الرصيد والصلاحيات.

## إعداد Supabase الحالي
المخطط الذي تمت مراجعته يحتوي على جداول مثل: profiles, rooms, room_members, chat_messages, wallets, families, family_members, agencies, agency_members, gifts, gift_transactions, vip_packages, user_vips, notifications, follows, blocked_users.
الجداول الموجودة وسياسات RLS هي المرجع؛ لا ينشئ التطبيق صلاحيات بديلة.
